Base64 인코딩 / 디코딩

텍스트를 Base64로 인코딩하고 디코딩합니다. UTF-8 안전 모드를 지원합니다.

디코딩할 Base64

텍스트를 입력하면 변환이 시작됩니다.
0 입력 글자 수 · 0 B

디코딩된 텍스트

0 출력 글자 수 · 0 B

최근 변환 기록 (이 브라우저에만 저장)

최근 5개의 변환 기록이 브라우저 저장소에 보관되며 업로드되지 않습니다.

아직 저장된 항목이 없습니다. 변환한 데이터가 여기에 표시됩니다.

사용 방법

  1. 1 인코딩을 선택하여 텍스트를 Base64로 변환하거나, 디코딩을 선택하여 원래 텍스트를 확인합니다.
  2. 2 UTF-8 안전 모드, URL 안전 문자(-, _), MIME 줄 바꿈 등 필요한 옵션을 지정합니다.
  3. 3 클릭 한 번으로 결과를 복사하거나 텍스트 파일로 바로 다운로드합니다.

주요 기능

  • 실시간 양방향 Base64 인코딩 및 디코딩
  • 한글, 한자, 일본어, 이모지를 완벽 지원하는 UTF-8 안전 모드
  • URL 안전 모드 (RFC 4648 §5) 및 패딩(=) 제어 옵션
  • MIME(64자) 및 PEM(76자) 규격 줄 바꿈 지원
  • Data URL 접두사 자동 인식 및 본문 디코딩
  • 실시간 문자 수, 바이트 크기 및 용량 변화율 통계 제공
  • 100% 브라우저 로컬 연산으로 완벽한 개인정보 및 데이터 보호

자주 묻는 질문

Base64 인코딩이란 무엇이며 언제 사용하나요?

'Base64는 이진 데이터를 64개의 출력 가능한 ASCII 문자(A-Z, a-z, 0-9, +, /)로 변환하는 인코딩 방식입니다. 이메일 및 텍스트 기반 프로토콜(MIME), JSON 및 API 통신, 쿠키나 URL에서 데이터를 안전하게 전송할 때 널리 쓰입니다.

표준 Base64와 URL 안전 Base64의 차이점은 무엇인가요?

'표준 Base64에 포함된 "+"와 "/" 문자는 URL 경로 및 쿼리 매개변수에서 특수한 의미를 가집니다. URL 안전 Base64(RFC 4648)는 "+"를 "-"로, "/"를 "_"로 대체하고 끝의 "=" 패딩을 생략하여 추가 인코딩 없이 URL이나 웹 토큰에서 안전하게 사용할 수 있도록 합니다.

한글이나 이모지를 인코딩할 때 오류가 발생하거나 깨지는 이유는 무엇인가요?

'자바스크립트 내장 window.btoa 함수는 Latin-1 단일 바이트(0-255)만 지원합니다. 다중 바이트인 한글이나 이모지를 전달하면 오류가 발생합니다. BrowserUtil은 기본적으로 UTF-8 안전 모드를 적용하여 표준 바이트 배열로 변환한 후 처리하므로 모든 유니코드 문자를 정확하게 처리합니다.

입력한 텍스트가 서버로 전송되나요?

'아니요. 모든 변환은 브라우저 내에서 JavaScript TextEncoder와 TextDecoder를 통해 로컬에서 실행되며 외부 서버로 전송되지 않습니다.
