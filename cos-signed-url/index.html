Tencent Cloud COS Signed URL Parser

Parse Tencent Cloud COS V5 signed URLs locally: decode q-sign-algorithm, q-ak, q-sign-time, q-key-time and q-signature, check expiry and inspect bucket and object details.

Paste a Tencent Cloud COS signed URL to inspect its signature, bucket and expiry.

Parsed locally in your browser — nothing is uploaded. Do not paste a production signed URL that is still valid: anyone with the full link can access the file.

How to use

  1. 1 Paste a COS signed URL containing q-sign-* parameters, or load the built-in sample.
  2. 2 Check the overview for the bucket, region, object key and the live validity status.
  3. 3 Read the meaning of each parameter and its decoded start and end times in the tables below.
  4. 4 Use Reset to clear the form back to its default empty state.

Features

  • Detects COS V5 signatures and explains all seven q-* parameters
  • Decodes %3B and converts Unix timestamps into local time and UTC
  • Live status: valid, not yet valid or expired, refreshed every second
  • Extracts bucket, APPID, region and object key from standard COS domains
  • Lists the headers and query parameters covered by the signature
  • Also works with custom domains as long as COS V5 parameters are present
  • 100% client-side — nothing is uploaded

Frequently asked questions

What are the q-* parameters in a COS URL?

COS V5 adds several q-* query parameters to a signed URL. They describe the signing algorithm, the caller's identity, the validity windows, and which headers or query parameters were covered by the signature.

Why does q-sign-algorithm say sha1?

sha1 refers to HMAC-SHA1, the only signing algorithm defined by COS Signature V5. It is a protocol requirement rather than a choice made by whoever generated the link.

Does the URL expose my SecretKey?

q-ak is the SecretId used to identify the caller. It is designed to appear in requests and is not the secret. The SecretKey is never placed in the URL. Still, a signed URL acts like a bearer token — do not share it before it expires.

What is the difference between q-sign-time and q-key-time?

q-sign-time is the validity window of this signature. q-key-time is the validity window of the temporary credential used to create it; with a permanent key the two are usually the same. Both use start;end in Unix seconds.

The link has expired. Can this tool renew it?

Only someone holding the SecretKey can create a new valid signature, normally your backend using the COS SDK. This tool only reads the URL locally and cannot extend, recompute or forge a signature.

Is my URL sent anywhere?

Yes. Parsing runs entirely in JavaScript inside your browser tab. The URL is never uploaded or stored.
